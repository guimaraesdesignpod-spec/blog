# Agents Need Control Flow, Not More Prompts: Why the Future of AI Reliability Lies in Deterministic Code, Not Clever Prompts

## The Ceiling of Prompt Engineering

If you've ever typed **"MANDATORY"** or **"DO NOT SKIP"** into a system prompt, you've already touched the ceiling of what prompting alone can achieve. A new wave of thought in the AI engineering community—crystallized in a post that hit #1 on Hacker News with over 500 points—argues that we are approaching a fundamental architectural inflection point. Reliable AI agents tackling complex, multi-step tasks need deterministic control flow encoded in software, not increasingly elaborate chains of natural-language instructions.

The argument is deceptively simple but profound: software scales through recursive composability. Libraries depend on modules, which depend on functions, which depend on predictable, deterministic behavior. Code exposes predictable behavior, enabling local reasoning. When you read a function, you know what it does. Prompt chains, by contrast, are non-deterministic, weakly specified, and difficult to verify. Every time an LLM processes a prompt, it is effectively rolling dice weighted by training data. The result is usually right, sometimes wrong, and occasionally catastrophically wrong in ways that are silent and hard to detect.

Imagine a programming language where every statement is merely a suggestion, and functions can return "Success" while internally hallucinating a completely different computation. Reasoning about such a system becomes impossible; reliability collapses as complexity grows. That, the argument goes, is precisely the world we inhabit when we build agentic systems purely on top of prompt chains.

## Why Prompts Hit a Wall

Large Language Models are probabilistic next-token predictors. They have no formal semantics, no guarantee of consistency, and no concept of state in the way a traditional program does. A prompt like "Always check the result before proceeding" is not a rule the model follows; it is a statistical pattern it attempts to approximate. Sometimes it works. Sometimes the model skips the check because the token probabilities favored moving forward. Sometimes it performs a check but misinterprets what it is checking.

The natural response to this unreliability has been to add more instructions. More constraints. More guardrails. More examples in the few-shot prompt. More chain-of-thought reasoning steps. But each additional layer of prompting adds complexity without adding determinism. It is like trying to build a skyscraper out of marshmallows: you can make it taller for a while, but the fundamental material properties never change.

Simon Willison, one of the most influential voices in practical AI engineering, has been documenting this convergence for months through his "Agentic Engineering Patterns" guide. In his podcast conversation with Heavybit, Willison described how the line between "vibe coding"—prompt-driven, unreviewed code generation—and responsible "agentic engineering" has started to blur in his own practice. Even for production systems, he now finds himself treating Claude Code as a semi-black box, trusting it for straightforward tasks without reviewing every line. The uncomfortable realization: if you cannot verify the output deterministically, trust becomes a statistical bet, not an engineering decision.

## The Case for Deterministic Control Flow

The alternative is to move logic out of prose and into runtime. Instead of hoping the LLM will remember to validate its output, encode that validation as a deterministic function. Instead of praying the agent will loop until completion, wrap the LLM call in an explicit state machine with defined transitions. Instead of relying on the model to self-correct, implement programmatic error detection and retry logic with exponential backoff.

This is not a new idea. Workflow engines, state machines, and deterministic orchestration have existed for decades. What is new is the need to hybridize them with LLM capabilities. The emerging pattern treats the LLM not as the system, but as a component within a deterministic scaffold. The orchestration layer—written in code, not prompts—handles state transitions, validation checkpoints, error recovery, and logging. The LLM handles the parts it is genuinely good at: unstructured reasoning, natural language understanding, creative synthesis, and human-like interaction.

OpenAI's own Codex CLI, released in version 0.128.0, hints at this direction with its `/goal` feature: the agent loops until it evaluates that the goal is completed. But even this is a prompt-level mechanism. The deeper insight from the HN discussion is that we need *programmatic* control flow: explicit state graphs, typed interfaces between steps, and verification at every transition.

## Three Post-Prompt Survival Strategies

The post on HN identified three approaches for dealing with an agent without aggressive error detection, each with its own problems:

**1. The Babysitter:** Keep a human in the loop to catch errors before they propagate. This works at small scale but fails as soon as you need the agent to run autonomously overnight, across hundreds of tasks, or in production where latency matters.

**2. The Auditor:** Perform exhaustive end-to-end verification after the run. This catches problems but is expensive and reactive. If the agent just corrupted a production database, verifying it after the fact does not un-corrupt the database.

**3. Prayer:** Vibe-accept the outputs. This is the default mode for many vibe-coding experiments, and it is exactly as reliable as it sounds.

The post's conclusion: none of these are satisfactory. The only real solution is to build agents with deterministic control flow from the ground up.

## What Deterministic Agent Architecture Looks Like

A deterministic agent architecture might look like this:

- **Typed State Machine:** Every agent has a finite set of states (e.g., `planning`, `executing`, `validating`, `error_recovery`, `complete`). Transitions between states are explicit, conditional on programmatic predicates, not on whatever the LLM feels like outputting.

- **Validation Gates:** Before any state transition, a deterministic validation function runs. Did the LLM output valid JSON? Does it conform to the expected schema? Have all required fields been populated? Are the values within acceptable ranges?

- **Tool Contracts:** When the agent calls an external tool, the call is structured (often through function calling / JSON mode) and the response is validated against a contract. The LLM does not get to freestyle the API call.

- **Retry and Circuit Breakers:** If validation fails, the system retries with a modified prompt or falls back to a simpler model. After N failures, it triggers a circuit breaker and escalates to a human.

- **Observability by Design:** Every state transition, every LLM call, every validation result is logged with a trace ID. The system is debuggable not by re-running the prompt and hoping for the same output, but by inspecting the deterministic execution graph.

This is how traditional distributed systems are built. It is how microservices communicate. It is how databases guarantee consistency. The only reason we have not been building agents this way is that the excitement around LLMs created a temporary blind spot where we forgot everything we knew about reliable software engineering.

## The Vibe Coding Trap

Andrej Karpathy's coinage of "vibe coding"—where you prompt an LLM and forget the code even exists—has become a Rorschach test for the industry. Some see it as democratizing software creation. Others see it as a recipe for technical debt at scale. The critical distinction, as Willison repeatedly emphasizes, is context. A personal script that only you use? Vibe away. A production system handling user data, financial transactions, or medical records? Deterministic reliability is not optional.

The danger is the normalization of deviance: every time a model produces correct output without close supervision, we increase our trust. Eventually we trust it at the wrong moment, and something breaks. In safety-critical engineering, this pattern is well-documented. In AI, it is happening in real time, at scale, and mostly unobserved because the failures are often silent.

## Where the Industry Is Headed

The good news is that the tooling is catching up. Frameworks like LangGraph, Prefect, and Temporal already provide deterministic workflow orchestration. The missing piece has been tight integration with LLM capabilities in a way that preserves determinism. Anthropic's own research into model interpretability—most recently with Natural Language Autoencoders for understanding Claude's internal states—suggests that even the labs building frontier models recognize that visibility and control are prerequisites for trust.

Cloudflare's recent restructuring, cutting 20% of its workforce to focus on the "agentic AI era," signals a broader industry shift. The companies that will thrive are not those that generate the most impressive demos, but those that build the most reliable infrastructure for autonomous agents.

The post that sparked this discussion ended with a pointed conclusion: "If you've ever resorted to MANDATORY or DO NOT SKIP, you've hit the ceiling of prompting." The ceiling is real, and we are collectively pressing against it. The way forward is not more prompts. It is better architecture. Deterministic control flow. Validation at every step. And treating the LLM as the powerful but probabilistic component it is, wrapped in the deterministic scaffolding that decades of software engineering have taught us how to build.

The future of reliable AI agents is not written in prompts. It is written in code.
